# Domain documentation

NexDrop uses a single domain context.

## Before exploring

- Read `CONTEXT.md` when it exists.
- Read the ADRs under `docs/adr/` that affect the area being changed.
- Preserve the terms and boundaries defined by those documents.

If `CONTEXT.md` does not exist, continue without creating it. Add or revise
domain documentation only when implementation work resolves a real terminology
or boundary decision.

## Architecture decisions

System-wide decisions live under `docs/adr/`. Surface conflicts with an existing
ADR explicitly instead of silently overriding it.
