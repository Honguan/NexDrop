# 自適應路由選擇

NexDrop 會獨立評估已驗證的 LAN、VPN、IPv4、IPv6 與 Node 候選路徑。探索只提供候選位址，不會授予信任。

## 狀態流程

```text
探索 -> 驗證 -> 評分 -> 競速 -> 選定 -> 傳輸
              \-> 拒絕
傳輸 -> 劣化 -> 重新競速 -> 遷移 -> 傳輸
```

直接路徑預設先行 350 毫秒；沒有可用直接路徑時，Node 立即啟動。驗證失敗、健康度低於門檻或端點資料不完整的候選會被排除。

## 評分

決定性評分會納入路由種類、近期握手延遲、吞吐量、失敗率與最近成功時間。分數相同時依直接路徑優先、路由種類及穩定候選識別碼排序。

## 遷移

切換路由不會重置整個檔案。發送端會比對已驗證分段雜湊與新路徑可用分段，只重傳缺少或不一致的內容。傳輸歷史會記錄選定路由、fallback 原因與遷移事件。

## 相容性

雙方必須共同協商 `adaptive_route_racing`。未支援時保留原本 LAN 優先、失敗後才改用 Node 的流程。

## 疑難排解

- 已探索到 LAN 但無法連線：檢查 AP 隔離與主機防火牆。
- VPN 未被選用：確認候選已驗證且近期有成功量測。
- IPv6 卡住：保留 IPv4 與 Node 候選，讓其他路徑完成競速。
- 經常 fallback：先查看失敗率與握手延遲，再調高直接路徑先行時間。
