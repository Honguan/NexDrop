# 多節點架構

## 第一階段：主要控制 Node 與次要資料 Relay

主要 Node 仍是使用者、裝置、授權、傳輸工作、包裝內容密鑰與 Relay 分配的唯一權威。次要 Relay 只儲存及提供加密分段。

Relay 註冊時提供身分金鑰、端點、區域、容量及健康狀態。主要 Node 依可用容量、失敗率、延遲與偏好區域選擇健康且非 draining 的 Relay。客戶端取得簽章短效 grant；Relay 不會取得 Node、管理員、資料庫或裝置憑證。

Relay 生命週期：

```text
已註冊 -> 健康 -> 排空中 -> 已移除
             |       |
             +-> 不健康
```

排空會停止新分配，但進行中的有效分段仍可使用。過期 grant 與孤立分段由有限批次清理工作校正及刪除。

## 可用性目標

單一 Node 安裝不需要額外設定。存在至少兩個 Relay 時，新工作會避開不健康或已滿端點；進行中傳輸可透過其他已授權端點重用已驗證分段。

## 第二階段：備援控制 Node

未來控制平面切換需要 PostgreSQL 複寫與提升、穩定 Node 身分、中繼資料復原、客戶端或 DNS 端點切換及明確 RPO/RTO。在 Relay 一致性與復原完成驗證前，不實作 active-active 控制 Node。
